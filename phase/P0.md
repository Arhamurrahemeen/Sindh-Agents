## Deviations from MVP_v1.md's P0 section (decided during build, see conversation for full reasoning)

- Tests are colocated (`foo.py` → `foo_test.py`, `foo.ts` → `foo.test.ts`) per CLAUDE.md §8,
  not in a separate `apps/backend/tests/` dir — CLAUDE.md §4's tree was the doc bug, superseded.
- No `pgvector` dependency — unused in MVP, adds it in the Phase 3 migration alongside its ADR.
- "BetterAuth" is hand-rolled session auth in FastAPI, not the BetterAuth library — supersedes
  ADR-008 (ADR write-up pending). `BETTER_AUTH_SECRET` env var name kept as-is for now.
- `docker-compose.*.yml` live under `infra/` (CLAUDE.md §4), not repo root (MVP_v1.md said root).
- RLS enabled on `excel_snapshots`, `excel_stock_items`, `order_intents`,
  `qdrant_collection_registry` in addition to the five tables db_schema.md explicitly marks —
  applying §0.3's blanket "every SME-scoped table" rule for consistency.
- `next` pinned to `14.2.35` (not `14.2.5`) and `vitest` to `4.1.10` (not `2.0.5`) —
  `npm audit` flagged 12 vulnerabilities incl. 2 critical on the original pins; both fixed
  within the same major version.
- UUIDv7 is hand-rolled in `src/ids.py` (RFC 9562, not stdlib) — no UUID library in the locked
  stack; drop this for `uuid.uuid7()` once the project moves to Python 3.14+.
- Local Postgres in `docker-compose.dev.yml` publishes on host port `5433`, not `5432` — this
  machine already had an unrelated project's Postgres container bound to `5432`. Internal
  container-to-container traffic (`db:5432`) is unaffected; only the host-side mapping moved.

## Bugs found while containerizing (2026-07-24) — fixed

Docker forced real boot verification that wasn't possible on this dev machine natively (no
Python 3.11, no MSVC Build Tools for `asyncpg`). That surfaced three real bugs:

1. **`apps/web/app/layout.tsx` validated env at module load**, which runs during `next build`'s
   page-data collection too — and the Docker image correctly excludes `.env.local` via
   `.dockerignore` (secrets shouldn't be baked into images), so the build crashed. Fixed: skip
   validation when `process.env["NEXT_PHASE"] === PHASE_PRODUCTION_BUILD`; validate only at
   real server startup (`next dev` / `next start`).
2. **`apps/backend/Dockerfile` never copied `alembic.ini`** into the image — `alembic upgrade
   head` failed inside the container with "no config file found." Fixed by adding it to the
   Dockerfile's `COPY`.
3. **`db_schema.md` §1.2/§1.3 spec a bug**: both partial indexes with `WHERE expires_at >
   now()` (`ix_sessions_expires`, `ix_otp_phone_active`) fail on real Postgres — partial-index
   predicates must be `IMMUTABLE`, and `now()` isn't (a partial index can't track a rolling
   "now" anyway). Fixed in the migration by dropping the `now()` half of each predicate;
   `ix_otp_phone_active` keeps `WHERE consumed_at IS NULL`. **`db_schema.md` itself still has
   the broken SQL — needs a doc fix**, not just a migration-file fix.

## What to expect

- `uvicorn src.main:app --reload --port 8000` boots; `GET /health` → `{"ok": true}` with an
  `X-Request-ID` header.
- `npm run dev` in `apps/web` boots on `:3000`; root page is blank (by design — P0 ships no UI).
- `alembic upgrade head` creates all 12 tables, enables RLS + policies on the 9 SME-scoped
  tables, and creates `app_role` (idempotent — safe to rerun).
- `NODE_ENV=production DEV_AUTO_SEED=true` → backend refuses to start (`RuntimeError`).
- `FEATURE_WHATSAPP=true` with any Twilio WA var empty → backend refuses to start.
- `resolve_channel("widget")` and `resolve_channel("whatsapp")` (in
  `src/channels/base.py`) both return a registered `OutboundChannel`; widget is the default.
- `docker compose -f infra/docker-compose.dev.yml up -d db backend web` boots all three
  containers; `backend` auto-seeds the pilot SME against the local Postgres on startup.

## Commands to run

```bash
# Docker (recommended — see README §"Run with Docker")
cd infra
docker compose -f docker-compose.dev.yml up -d db
docker compose -f docker-compose.dev.yml run --rm backend alembic upgrade head
docker compose -f docker-compose.dev.yml up -d backend web
curl http://localhost:8000/health

# Native (alternative — requires Python 3.11, see README if not installed)
cd apps/backend
py -3.11 -m venv .venv && .venv\Scripts\activate
pip install -e ".[dev]"
cp ../../.env .env
alembic upgrade head
uvicorn src.main:app --reload --port 8000
pytest

# Frontend (new terminal, either path)
cd apps/web
npm install
npm run typecheck
npm run test
npm run build
npm run dev
```
