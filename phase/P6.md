## 1. Why this is a scope reversal, not a gap fill

`docs/tools_spec.md` (current, unmodified) explicitly says:

> "MVP: SME's Excel file is uploaded once during onboarding, stored as a snapshot
> in the DB... Reingest on Excel re-upload happens via `POST /api/excel/reingest`
> (**out of scope for MVP**; pilot SMEs re-upload manually, we re-run seed script)."

`docs/dashboard_spec.md` (current, unmodified) also lists **"settings page"** under
"Explicitly not shipping in MVP." An upload page arguably falls near that line, so
this proposal scopes it narrowly (inventory upload only — no billing, no profile,
no notification prefs) to avoid quietly expanding that boundary.

Building this now is a deliberate, informed reversal of both calls — not an
oversight being corrected. If approved, the four docs below get updated to say so
explicitly, so nothing drifts silently out of sync with what the code does.

## 2. What already exists (confirmed by reading the code, not assumed)

- `excel_snapshots` / `excel_stock_items` tables already exist (`docs/db_schema.md`
  §1.9/1.10) with exactly the shape this feature needs, including a partial unique
  index (`ux_excel_active_per_sme`) enforcing one active snapshot per SME — the
  schema looks like it was designed anticipating this feature, just never wired up.
- Only populated today by `apps/backend/seeds/pilot_sme.py` — hardcoded Python
  tuples, no file ever parsed.
- `read_excel_stock` tool / `ExcelStockRepository` already read from these tables
  — once real rows land in them via upload, the existing buyer-facing stock
  lookup flow picks them up with **zero changes** on that side.
- No file-upload precedent anywhere in the backend (no `UploadFile`, no
  `python-multipart`, no `openpyxl`/`pandas` dependency yet) — this is new
  plumbing, not a variation on an existing pattern.
- No "agent settings/detail" dashboard page exists yet — only home,
  `/conversations`, `/conversations/[id]`. A new route is needed.
- **Found a real blocker**: `apps/web/lib/backend-fetch.ts`'s `proxyToBackend`
  (the thing every other dashboard API route uses) hardcodes
  `content-type: application/json` and reads the body via `request.text()`. That
  would corrupt a binary `.xlsx` upload and drop the multipart boundary. This one
  route needs its own dedicated proxy, not the shared helper.
- Auth pattern to reuse as-is: `AuthSession` / `require_session` from
  `src/middleware/auth.py`, exactly as `conversations.py` and `audit.py` already
  do it.

## 3. Proposed doc changes (this is the actual content to review)

### 3.1 `docs/tools_spec.md` §"Excel source of truth" — replacement text

Column mapping for the uploaded sheet:

| Excel column | DB field | Notes |
|---|---|---|
| SKU | `sku_canonical` | required |
| Aliases | `sku_aliases` | optional, comma-separated → parsed to `text[]` |
| Stock | `stock` | required, integer ≥ 0 |
| Unit | `unit` | required, one of `pieces/meters/kg/liters/boxes` (case-insensitive) |
| Price | `price_per_unit` | required, ≥ 0, 2dp |
| Reorder Threshold | `reorder_threshold` | optional, default 0 |

Behavior: `POST /api/excel/reingest`, multipart upload, session-authenticated.
SHA-256 hash of the raw file bytes computed; if it matches the current active
snapshot's `snapshot_hash`, the upload is a no-op (idempotent re-upload of an
unchanged file). Otherwise: deactivate the current active snapshot, insert a new
one as active, bulk-insert its rows — all in one transaction.

### 3.2 `docs/api-contract.md` — new endpoint contract

```
POST /api/excel/reingest
Auth: session cookie required (403 if missing/invalid)
Request: multipart/form-data, field name "file", .xlsx only

Success (200):
{ ok: true, data: { snapshotId: string, itemCount: number, ingestedAt: string } }

Errors:
400 BAD_REQUEST     — missing required column, bad unit value, negative stock/price, empty file
401 UNAUTHENTICATED — no/invalid session
413 PAYLOAD_TOO_LARGE — file exceeds size cap (proposed: 2MB)
```

Row cap proposed: 500 rows (pilot SMEs run ~15-20 SKUs per `db_schema.md`'s own
seed-scale notes; 500 is generous headroom, not a real constraint).

### 3.3 `docs/dashboard_spec.md` — new screen

New page (route TBD, proposed `/inventory`), reachable from the home page's
existing agent card. States:
- **Empty** — no snapshot yet: "Abhi tak koi stock sheet upload nahi hui."
- **Uploading** — spinner, disabled form.
- **Success** — "N items upload ho gaye" + last-ingested timestamp + filename.
- **Validation error** — list of specific row/column problems, not just "failed."

Note to add next to the existing "settings page not shipping in MVP" line:
clarify that this inventory-upload page is a narrow, separate thing from the
general settings page that line refers to (no billing/profile/notification prefs
here).

psql check, confirm old snapshot deactivated, then ask the widget about a newly
uploaded SKU and confirm the reply reflects it — a real round trip, not just unit
tests.

## 6. Shipped

**Goal:** SME uploads a `.xlsx` from `/inventory`; it replaces the active stock
snapshot in one transaction; the widget's next reply reflects the new numbers.
Re-uploading an unchanged file is a no-op; a bad row rejects the whole file.

**Files touched:**
- `apps/backend/pyproject.toml` — added `openpyxl`, `python-multipart`; mypy override for `openpyxl.*`
- `apps/backend/src/repositories/excel_stock_repository.py` — `get_active_snapshot()`, `replace_snapshot()` (transactional deactivate-old/insert-new/bulk-insert)
- `apps/backend/src/services/excel_ingestion_service.py` — column/row parsing and validation, hash no-op check
- `apps/backend/src/services/excel_ingestion_service_test.py` — unit tests on the parsing/validation logic (valid file, blank rows, missing column, bad unit, negative price, non-integer stock, empty file, row cap)
- `apps/backend/src/api/excel.py` — `POST /api/excel/reingest`
- `apps/backend/src/main.py` — router registration

- `apps/web/lib/api.ts` — `reingestResponseSchema`, `apiFetchFormData` (multipart variant of `apiFetch`, which hardcodes JSON content-type)

**What to expect:**
- Dashboard → agent card → Inventory → pick a `.xlsx` → upload starts immediately (no separate submit tap).
- Success state shows item count, filename, ingested timestamp.
- Re-uploading the same file shows the no-op notice instead of implying a change.
- A file with a bad row shows the specific row/column problem verbatim (e.g. "Row 4: Unit must be one of boxes, kg, liters, meters, pieces").
- Ask the widget about a SKU from the new sheet — reply reflects the new stock/price with zero changes to `read_excel_stock`.
